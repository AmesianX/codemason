## 주요 기능

짝을 이루는 서버는 [dspark-serve](https://github.com/AmesianX/dspark-serve)
(GLM-5.3-Flash, DGX Spark 2대 TP2)다. ⓢ 표시는 서버 기능을 클라이언트가 쓰는 항목이다.

| 기능 | 내용 |
|---|---|
| **사실상 무한 프리픽스 캐시** ⓢ | 서버가 GPU 에서 밀려난 프리픽스 KV 를 노드당 NVMe 200GB 에 보관하고, 재기동 후에도 살려 둔다. 긴 세션을 이어 가거나 `/resume` 으로 다시 열어도 앞부분을 다시 읽지 않고 캐시에서 이어 받는다. |
| **요청별 `/ab`** ⓢ | `/ab off\|on\|auto` — 실시간 검열 해제(o_proj rank-24 어댑터). 요청마다 `vllm_xargs.ab_scale` 로 실어 보내고, 서버에는 전역 스위치가 없다(`POST /ab` = 410). 같은 서버를 쓰는 다른 사람의 출력에는 영향이 0 이다 — 같은 배치 이웃 요청의 logprob 비트 동일로 검증했고, 켠 요청은 공유 프리픽스 캐시를 읽기만 하고 쓰지 않아 캐시로도 번지지 않는다. `auto` 는 사용자 턴의 첫 요청(수락을 결정하는 요청)에만 켠다. 검열 해제는 거절뿐 아니라 "그런 건 없다"고 말하는 능력도 지워서 작화가 늘기 때문이다(4/60 → 18~22/60). |
| **병렬 서브에이전트 + 우선순위** ⓢ | 최대 3개 동시 실행. 서브에이전트 요청은 vLLM priority 1 이라 대기열에서 메인 대화가 먼저 처리된다. 서브에이전트 컨텍스트 예산은 부모 기준의 30%, 동시 합계 90%. |
| **결정적 출력** ⓢ | temperature 0 에서 배치 구성·부하·재기동과 무관하게 같은 출력(서버 배치 불변). |
| **웹 검색** | 자체 호스팅 SearXNG 를 먼저 쓰고, 안 되면 duckduckgo·brave·mojeek·google 을 직접 부른다. 결과가 빈약하거나 엔진이 막히면 서버가 스스로 신원 있는 브라우저 검색으로 승격한다 — 클라이언트는 이걸 지정할 수 없다. |
| **이미지 입력** ⓢ | 한 요청에 최대 5장. 텔레그램으로 받은 사진도 그대로 넘긴다. |
| **암호화 게이트** ⓢ | 원격 접속 시 요청 본문을 AES-GCM 으로 암호화해 보낸다. 키는 전송되지 않는다 — 키를 가진 것 자체가 자격증명이다. |
| **원격(텔레그램)** | `/remote` — 폰에서 지시·도구 승인·질문 응답. 긴 결과는 파일로 받는다. |
| **무인 실행** | `/goal`(매 턴 주입되는 목표) + 완료 게이트(`/goal gate add <cmd>`) + `/keepgoing`. |
| **정확한 토큰 계산** | 서빙 모델의 토크나이저를 동봉해, 자동 압축(컨텍스트 88%)·창 검사·사용량을 추정이 아닌 실제 값으로 계산한다. |
| **모델별 샘플링 자동** | `sampling_profile: "auto"` — GLM 은 제조사 권장값(temperature 1.0, top_p 0.95, top_k 없음)을 쓰고 config.json 의 값은 무시한다. `"manual"` 이면 config.json 그대로 보낸다. |
| **다국어 UI** | `/language`. 영어 원문이 번역 키다. |

## 설치

```bash
./setup.sh                 # 리눅스·macOS — 빌드 후 실행 파일과 vendor/ 를 함께 배치
setup.bat                  # 윈도우 — 설치 경로를 유저 PATH 에 등록 (새 터미널부터)
cargo build --release      # 직접 빌드할 때
```

실행 파일만 다른 곳으로 복사하면 동봉된 ripgrep 을 잃고 느린 네이티브 워크로
떨어진다. `setup.sh` / `setup.bat` 이 둘을 같이 옮기는 이유다.

## 사용

```bash
codemason                  # REPL — 타이핑은 큐잉되고 작업 중에도 입력을 받는다
codemason -p "..."         # 프린트 모드. 한 번 묻고 결과만 출력
codemason --help
```

모델 백엔드는 설정으로 고른다 (`vllm` 권장 / `llamacpp`). OpenAI 호환 엔드포인트를 쓴다.

## 실행 엔진 권장 사항

> **llama.cpp 기반 실행은 구현되어 있으나, 성능과 구현 완성도를 고려하여 사용하지
> 않을 것을 강력히 권고합니다. 본 프로젝트에서는 vLLM 사용을 권장합니다.**

현재 본 프로젝트의 b12x 커널은 vLLM에만 구현되어 있으며, 프로젝트 실행 환경에서
prefill 1,300+ 토큰/초, decoding 35\~40+ 토큰/초의 성능으로 쾌적한 사용이 가능합니다.
반면 llama.cpp는 최대한 최적화한 후에도 prefill 450+ 토큰/초, decoding 25\~30 토큰/초
수준에 머물러, 체감 성능에서 상당한 차이를 보였습니다.

또한 사용한 llama.cpp 구성에서는 2노드 텐서 병렬이 기본적으로 지원되지 않아 이를 직접
구현하고 추가 최적화까지 진행했으나, 여전히 만족할 만한 체감 성능을 확보하지 못했습니다.

이러한 이유로 현재 개발과 최적화는 vLLM에 집중하고 있습니다. llama.cpp는 기본적인 실행
기능만 구현된 상태로, 추가 기능 구현과 충분한 테스트가 이루어지지 않았으므로 사용을
권장하지 않습니다.

## 구성

```
src/
├── main.rs            진입점
├── cli.rs             REPL UI — 입력 엔진과 출력 라우팅
├── cli_repl.rs        REPL 루프
├── query.rs           에이전트 루프 — 모델 호출, 도구 실행, 자동 압축,
│                      최대 토큰 복구, 반복 호출 제동
├── print_runner.rs    -p 모드 실행기
├── task.rs / tasks/   백그라운드 작업
├── tools/             Read · Write · Edit · Bash · Glob · Grep · Agent ·
│                      WebFetch · MCP · TodoWrite · AskUserQuestion …
├── services/          백엔드 어댑터 (vllm, llamacpp), 압축, 비전, A/B
├── remote/            원격 봇 풀
├── state/             세션 · 재개 · 트랜스크립트
├── constants/         프롬프트와 스키마
├── utils/             설정, 파일, 포맷, 권한 상승, 완성, 암호화 …
└── locales/           다국어 (영어 원문이 키)
```

### 동작 개요

1. **입력** — REPL 이 입력을 큐에 넣는다. 모델이 도는 중에도 타이핑이 막히지 않고,
   다음 턴에 steering 으로 들어간다.
2. **에이전트 루프** (`query.rs`) — 모델을 부르고, 돌려받은 도구 호출을 실행하고,
   결과를 다시 넣는다. 대화가 길어지면 자동으로 압축하고, 같은 호출이 반복되면 제동을 건다.
3. **도구** (`tools/`) — 각 도구는 스키마와 실행부를 함께 가진다. 파일 수정은
   읽기를 선행 조건으로 두고, 셸은 권한 확인을 거친다.
4. **상태** (`state/`) — 세션을 트랜스크립트로 남겨 재개할 수 있게 한다.
